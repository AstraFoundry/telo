# Infrastructure Layer

The infrastructure layer implements the abstractions that the domain layer defines. It contains all framework, database, and external-service code.

> **Telo mapping.** `backend/infrastructure/tdlib` (libtdjson and its generated bindings), `telegram/live` (TDLib adapters), `telegram/demo` (the in-memory workspace), `agent` (gateways, OAuth, catalog, stores, demo gateway) and `storage` (atomic and sealed files, the keychain). The TypeScript example below is illustrative.

## What belongs in `infrastructure/`

- **Repository implementations** — concrete persistence for domain aggregates.
- **External service clients** — HTTP clients, SDK wrappers, message publishers.
- **Messaging adapters** — event bus, queue producers/consumers.
- **Configuration and environment access** — reading env vars, config files.
- **Framework-specific code** — ORM mappings, database migrations, cache integrations.

## Rules

- Infrastructure depends on `domain` and `application`. It never contains business rules.
- Implement domain ports, do not invent new interfaces unless needed.
- Telegram adapters map TDLib's member status and permissions onto the chat's send flags only; the decision to allow a send is `tg.RequireSend` in the domain, so the TDLib and demo adapters cannot diverge.
- Keep mapping code explicit. Transform between persistence models and domain entities in one place.
- Do not leak infrastructure details into `application` or `domain`.

## Example

```ts
// infrastructure/persistence/sql-order-repository.ts
export class SqlOrderRepository implements OrderRepository {
  constructor(private readonly db: Database) {}

  async findById(id: OrderId): Promise<Order | null> {
    const row = await this.db.query("orders").where("id", id.value).first();
    return row ? this.toDomain(row) : null;
  }

  async save(order: Order): Promise<void> {
    const row = this.toPersistence(order);
```

## External services

- Wrap third-party APIs in thin adapters.
- Define the port in `domain/` or `application/` and implement it here.
- Failures in external services should be translated into domain or application errors, not leaked as raw HTTP errors.
- Provider failures become the domain's outcomes (`ErrRejected`, `ErrUnreachable`, `ErrRequestFailed`); response bodies never leave the adapter.

## TDLib

- `tdlib` loads `libtdjson` with `purego` (no cgo) from the app's resources, or `build/tdlib-native` in development, and checks its version.
- `tdlib/tdapi` is generated by `cmd/tdgen` from the pinned `td_api.tl`, limited to the functions and types listed in `tdapi.list`. `make tdapi` regenerates it; `make generated` fails when it is stale.
- `telegram/live.Accounts` keeps the account registry and one TDLib directory per account, each database encrypted with a key held in the system credential store. `live.Session` answers TDLib's parameters, maps updates to domain events and implements `tg.Repository`.
- `telegram/demo` implements the same ports in memory for `make demo` and every UI test.

## Agent gateways

- `agent.HTTP` streams the configured provider: OpenAI-style chat completions (OpenAI, Groq, xAI, Kimi, DeepSeek, Mistral and compatible servers), Anthropic messages and Gemini, over server-sent events, and loops tool calls up to the configured step limit. Kimi's coding models fix their sampler, so the request leaves temperature out.
- `agent.OAuth` signs in with PKCE on a loopback redirect, or the device-code grant, and renews tokens. `agent.Catalog` lists a vendor's models with the stored credential.
- `agent.Demo` answers from the prompt's markers alone, for the demo workspace and tests.

## Agent tools

The application assembles the model's tools per run (`application/agent/tools.go`): `inspectWorkspace` (the visible chats and messages, only when workspace inspection is allowed), `listChats`, `readChatHistory`, `searchChatMessages` and `searchGlobal` (read-only, redacted before they reach the provider), and `configureTriggerRule` / `configureScheduledTask` for the agent's own automation. Sending is not a tool: delivery belongs to automation.
