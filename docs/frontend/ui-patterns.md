# UI Patterns

This document defines how UI is written in this project. The goal is a consistent, maintainable, and accessible interface.

## Language

- All user-facing copy must be in English unless the user explicitly asks for another language.
- All code, comments, prop names, and CSS custom properties must be in English.

## No hardcoded strings

- Every user-facing string must come from a centralized source: i18n keys, design-system tokens, or a constants file.
- Do not write labels, placeholders, or error messages directly in components.

```tsx
// ✅ Good
import { t } from "shared/i18n";

<Button>{t("order.submit")}</Button>;
```

```tsx
// ❌ Bad
<Button>Submit order</Button>
```

## No redundant copy

- Do not repeat information already shown by a title, icon, selected state, or surrounding section.
- Prefer concise labels over explanatory text when the state is self-evident.
- Remove disabled placeholder actions unless they teach a real next step.

```tsx
// ❌ Bad
<div>
  <h1>Orders</h1>
  <p>This section shows your orders.</p>
</div>
```

```tsx
// ✅ Good
<div>
  <h1>{t("orders.title")}</h1>
  <OrderList />
</div>
```

## Semantic styling

- Use semantic design tokens instead of physical colors.
- ❌ Avoid: `bg-white`, `text-black`, `zinc-500`.
- ✅ Prefer: `bg-background`, `text-foreground`, `border-border`, `text-muted-foreground`.
- Theme differences must live in one place (global theme file or CSS variables). Do not scatter `dark:` or media queries across components. When one theme needs a contrast tweak, reach for an alpha variant of a semantic token (e.g. `text-foreground/70`) that reads correctly in both themes.
- Elevation is expressed with layered transparent shadows, not hairlines. The workspace shell paints `bg-background`; the central column floats on it as a card (`bg-card rounded-l-2xl shadow-column`, token defined per theme in `frontend/src/app/styles/index.css`), and its shadow carries the separation. When the agent panel is open the card's right corners round too (`rounded-r-2xl`) and the panel sits borderless on the shell background, mirroring the left sidebar. Reserve `border-*` for structural separations inside content (Settings section dividers, the sidebar account row) — never to partition the app shell, and never doubled against a shadowed edge.
- Outgoing chat bubbles use the beui `MessageBubble` `tint` variant (accent-tinted surface, foreground text), matching Telegram's accent-family outgoing bubbles. The `solid` variant inverts `bg-foreground`/`text-background`, which reads as near-black in light theme and glaring white in dark theme; do not use it for chat bubbles.

## Deslop scan suppressions

The `kill-ai-slop` project skill ships a scanner (`.agents/skills/kill-ai-slop/scripts/scan.mjs`) that flags AI-slop visual and copy tells in source. It runs on demand through the skill; it is not wired into `package.json` scripts or CI.

Hits that have been reviewed and confirmed intentional are pinned in source with comment directives:

- `deslop-ignore` — suppress hits on the same line.
- `deslop-ignore-next-line` — suppress hits on the next line.
- `deslop-ignore-file` — suppress hits in the whole file.

Each directive accepts optional tell ids (e.g. `/* deslop-ignore-next-line 19 */`) to suppress only those tells. Always prefer the id-scoped form so new tells on the same lines still surface, and add a suppression only after the hit has been defended — never to silence the scanner preemptively. `deslop-ignore-next-line` must sit on the line immediately above the line the scanner reports; inside a multi-line JSX element the hit lands on the `className` attribute line, so the directive belongs between the previous attribute and `className`, not above the element's opening tag.

Current uses: tell `12` (flat type hierarchy) on compact panel headings and tell `19` (max-radius) on the avatar and unread-badge pills — both deliberate parts of the Telegram-style chat UI. Avatars use the shared `Avatar` primitive (`frontend/src/shared/ui/avatar.tsx`, exported from the `shared/ui` barrel); unread pills stay hand-composed because the beui registry has no unread-count `Badge` yet — the upstream registry request is tracked in `.workspace/todo/telo.md`, and the pill suppressions should be revisited once one lands.

## Component and icon sources

- Import UI primitives only from `shared/ui`; that module re-exports the installed BEUI registry source plus a small set of local primitives that fill registry gaps (`Avatar`, `LoadIndicator`).
- Compose product-specific rows and regions from those primitives. Do not create a parallel button, input, select, switch, tooltip, message, or prompt implementation.
- Use `@phosphor-icons/react` for system icons. Icon-only controls require a tooltip and accessible name.
- The assistant/agent icon is `Sparkle` everywhere (panel header, message avatars, the agent toggle, empty states), matching the beui agent components (`AgentActivity` rows use it too). Never use `Robot`. Keep the toggle's `weight={open ? "fill" : "regular"}` outline/fill state convention.
- Keep notification copy out of the renderer surface and send notifications through `window.telo.shell.notify`. Status: the capability is implemented end to end (contract, preload, main handler) but no renderer code calls it yet. Decision: retain the channel as ready-to-use; the first intended integration point is unread-message notifications.

## Settings and preferences

- Preference reads/writes go through per-key hooks built with `createPreferenceStore` (`frontend/src/entities/preferences/model/preference-store.ts`) — the theme model generalized: a module-level external store loads the persisted value once, `select` publishes the new value optimistically, and a failed write re-sources from `preferences.get()`. Values that are visible outside React pass an `apply` side effect. Only app-wide values (accent, message text size) load eagerly at module scope; the rest load on first subscriber. The hooks live in the `entities/preferences` slice (`model/hooks.ts`) so any layer can subscribe; Settings edits apply live in the conversation sidebar (row timestamps), the conversation view (message times, `--message-font-size`), and the message composer (send-with-Enter) without a remount.
- A preference that a store reads outside React cannot be subscribed to by that store: `entities/chat` and `entities/preferences` are the same layer. The composition root carries it instead — `useChatPreferenceSync` (`frontend/src/app/chat-preference-sync.ts`) reads the notification and muted-chat hooks and pushes them into `chat-store.applyPreferences`, which also recomputes the keyword badges it holds in state. So those toggles land on the badges and the next notification immediately, not on the next workspace load. The push waits for `usePreference().loaded`, the hydration flag `createPreferenceStore` publishes once `preferences.get()` answers: before that a hook reports its own default, which would overwrite the store's conservative boot state. `chat-store.load()` still seeds the mirror, so the bridge only carries changes.
- Settings is a nav rail plus a detail pane, not one long column — the shape Telegram Desktop, macOS System Settings and every settings pattern on Mobbin converge on once a surface passes a screenful. `SettingsNav` (`frontend/src/pages/settings/ui/settings-nav.tsx`) owns the section list and the search field; each pane is its own component under `ui/sections/`, and the agent pane reuses the `configure-agent` feature form rather than restating it. Only the pane scrolls: `main` is a grid item, so it needs `h-full min-h-0 overflow-hidden` for the pane's `overflow-y-auto` to have a bound to scroll against — without `min-h-0` the column grows to its content and the scrollbar never appears, which is what made the old panel unreachable past the fold.
- Search matches a label plus an alias list per section (`SETTINGS_INDEX`), so "dark", "font" and "cache" find Appearance, Appearance and Storage. Aliases are the point: a reader searches for the setting, not the drawer it was filed under. No match renders an explicit empty state rather than a blank rail.
- A setting renders through the row primitives in `shared/ui/settings-row.tsx`: `SettingsGroup` for a titled card, `SettingsRow` for label-left/control-right, `SettingsStackedRow` when the control needs the full width (sliders), `SettingsLinkRow` for navigation with a disclosure chevron. Rows are 44px minimum. A row whose control is a `Switch` wraps its whole text stack in the `label`, so the row itself is the 40px target rather than the switch alone; the description carries `aria-hidden` so it stays out of the control's accessible name. Multi-option choices use the beui `RadioGroup` or `Select`; bounded numbers use the beui `RangeSlider` with the value shown next to the label in tabular numerals.
- Pane switching is the one animation here: a 140ms opacity-and-4px-offset cross-fade on the pane, keyed by section id. Rows, groups and the rail carry no entrance animation — a settings pane is opened repeatedly and read, which is the high-frequency tier where motion becomes a tax. The pane transition reads `useReducedMotionConfig()` and collapses to an instant swap.
- Simple controls autosave on change; only the agent form, which is a set of interdependent fields, has an explicit Save. That split is the hybrid model every current client uses — a toggle that needs confirmation is a toggle that lies about its state.
- The agent pane mounts the `manage-agent-automation` feature below the `configure-agent` form: two sections, Trigger rules and Scheduled tasks, each a list with an add action and per-row Switch enable toggle plus edit and delete icon buttons. Agent-authored entries carry a `Sparkle` marker with the `copy.createdByAgent` tooltip, so the user can tell what the agent configured for itself. Create and edit happen in `CenterMorphModal` dialogs (`TriggerRuleDialog`, `ScheduledTaskDialog`): comma-separated match fields, an optional regex pattern, cron expression or `datetime-local` one-shot schedule, and the shared `DeliveryModeRadio` — draft-only is preselected, so auto-send only ever ships as an explicit pick. Rule rows summarize the match dimensions (AND across dimensions, OR across keywords) flattened into one read-out; task rows show the schedule and the derived `nextRunAt`. Writes are not optimistic: the bridge answer (or a full re-list after a save) is what moves the state, so a rejected write leaves the view unchanged rather than needing a revert. `useAgentAutomation` re-lists both collections on every `agent:automation-event` and escalates only `draft-conflict` and `error` outcomes to a system notification through `window.telo.shell.notify` — successful deliveries are already visible in the chat surface.
- Token override points live in `frontend/src/entities/preferences/model/hooks.ts`. A non-blue accent writes `--primary` / `--primary-foreground` / `--ring` inline on `documentElement` — same lightness/chroma as the blue defaults in `app/styles/index.css`, only the hue differs, with separate light and dark sets. Blue removes the inline overrides so the stylesheet defaults win again, and a `MutationObserver` on the `dark` class re-applies the matching set when the theme flips. The message text size publishes as `--message-text-size`; message surfaces size with `var(--message-text-size, 14px)`.
- Destructive account actions confirm in two steps on the beui `StatefulButton`: the first click arms the confirm label (destructive tokens), the second executes and the button's own loading/success states carry the async feedback. Demo-workspace logout additionally clears the `demoWorkspace` preference so the shell returns to onboarding; the backend demo logout is a no-op by design. Onboarding has no demo action — demo is a process launch flag.

## Context menus

- Context menus come only from the beui `ContextMenu` family via `shared/ui`. Right-click, the ContextMenu/Shift+F10 keyboard path, and the ordinary touch long-press are built into the component; consumers never wire their own `contextmenu` listeners. The sticker grid is the deliberate exception: it disables the menu's touch hold because Telegram assigns that gesture to transient sticker preview, while right-click and keyboard still open the same menu. The portal's morph origin, keyboard navigation, typeahead, and reduced-motion fallback are likewise component-owned.
- Trigger targets: the chat row in the conversation sidebar and the message bubble in the conversation view. The trigger wraps the innermost element that carries the meaning (the row button, the bubble), so header and footer chrome stays outside the menu's hit area and left-click selection behavior is untouched.
- Item order mirrors Telegram desktop: mark read/unread → pin/unpin → mute/unmute on chat rows; Reply → Edit (outgoing messages only) → Copy → Forward → separator → Delete on message bubbles. A destructive item, when one exists, goes last after a `ContextMenuSeparator` with `tone="destructive"`.
- Toggle labels reflect the current state (`Mark as read` vs `Mark as unread`, `Unpin` vs `Pin`, `Unmute` vs `Mute`) and come from `copy.ts`; each item pairs a `size-4` Phosphor icon (`Checks`, `PushPin`/`PushPinSlash`, `Bell`/`BellSlash`, `Copy`, `ArrowBendUpLeft`, `PencilSimple`, `ArrowFatLineRight`, `Trash`) with its label.
- The message menu is selection-aware: it snapshots `window.getSelection()` when the menu opens (`onOpenChange`), not at render time — the portal keeps its items mounted while closed, so render-time reads go stale. A non-empty selection offers `Copy Selected Text`; otherwise `Copy Text` copies the whole message body via `navigator.clipboard`.
- Reply/Edit do not act on the message directly: they set the chat store's `composerTarget`, and the composer's preview bar (accent bar, title, truncated preview, cancel control) carries the pending state until send or cancel.
- Reacting to a message is a hover-rail action and a context-menu row: the rail (Reply, React, AI) appears on pointer hover or focus-within, and React opens the `react-to-message` picker's `MorphPopover` with the emoji from `getMessageAvailableReactions` (top, then recent, then popular). The same allowed set leads the right-click menu (Telegram Desktop / Web A). The rail hangs off the bubble's outer bottom corner in the gutter — tdesktop reserves 56px beside every bubble (`msgMargin`) precisely so hover actions never cover content, and Web A's `.quick-reaction` is a 28px disc at the bubble's edge; here each action is a 28px disc inside a 40px pointer target, with no card chrome.

## Dialogs

- Modals come only from the beui `CenterMorphModal` family via `shared/ui`. Controlled usage passes `open` + `onOpenChange`; `CenterMorphModalContent` owns the backdrop, focus trap, Escape dismissal, close control, and reduced-motion fallback. Its `ariaLabel` and `closeButtonLabel` come from `copy.ts` — never accept the component's hardcoded English default.
- Confirmation dialogs (message deletion) state the consequence in one sentence and offer a ghost cancel plus a single danger action: the beui `Button` has no destructive variant, so the confirm button is `variant="primary"` with a destructive token override (`bg-destructive text-primary-foreground hover:bg-destructive/90`).
- Picker dialogs (forward target) list conversations as full-width ghost `Button` rows that reuse the sidebar chat-row composition (`Avatar` + title); this is a composition of existing primitives, not a new row component.

## Onboarding

- The onboarding page (`frontend/src/pages/onboarding/ui/onboarding-page.tsx`) holds a local `welcome | auth` step. Welcome shows the logo, title, subtitle, and the `copy.startMessaging` primary action; the auth step renders `ConnectionStepContent` full-screen with a top-bar back button. The skip-to-content link convention from Accessibility applies here too.
- Steps transition as full-screen pages with a directional slide (`AnimatePresence mode="popLayout"`, `motion.section` keyed by `viewId`). Forward steps enter from `x: 48`, back steps from `x: -48`, with `opacity`, `scale`, and `blur` settling over ~300 ms using the beui `EASE_OUT` token. The first render does not animate.
- Steps are `phone → code → password`, driven by `useConnectionForm` (`features/connect-telegram/model`): local step state follows the store's auth status, so a submitted or failed attempt keeps the user on the current step until the backend pushes the next one. The code step header carries the full international number plus a pencil icon-button (`copy.editPhoneNumber`, with tooltip) that returns to the phone step; the password step titles itself with `copy.connectionPassword`.
- The phone step separates country/region from the national number, mirroring Telegram's own clients (e.g. Nicegram-Android's `LoginActivity`). Country data comes from `libphonenumber-js` metadata plus `Intl.DisplayNames` English region names (`shared/config/countries.ts`) — never a hand-maintained list. The picker is the beui `Combobox` (`CountryCombobox` in the feature slice), searchable by name and dialing code; the default country derives from `navigator.language`.
- Typing or pasting a number with an international "+" prefix re-selects the country by longest dialing-code match (shared codes resolve to libphonenumber's main territory: 1 → US, 7 → RU, 44 → GB) and keeps the national remainder in the field. Until a code matches, the pending "+…" entry stays verbatim and the country prefix steps aside.
- The phone field shows the dialing code as an animated left prefix (`DialCodePrefix`: vertical swap with blur, 180 ms `EASE_OUT`, reduced-motion falls back to opacity) and reserves its width via an inline `paddingLeft` computed from the code length.
- The code step uses the beui `OTPInput` with five slots (Telegram codes are five digits), auto-submitting via `onComplete`; errors render through its `status="error"` shake plus inline message.
- Application credentials are build-time injected, so the renderer never asks for them. When `configuration.applicationCredentialsConfigured === false` the flow renders only a `role="alert"` configuration error (`copy.credentialsMissing`).
- Submission errors surface through the field's own error channel (beui `Input` `error` prop / `OTPInput` `status`) — never a standalone error paragraph next to the form.
- The entrance stagger on welcome uses the beui `TextReveal` for the text items (title, then subtitle with a small `delay`); the logo and buttons stay static because the registry has no generic reveal container for arbitrary elements. Note that `TextReveal` splits copy into per-word spans, so jsdom accessible-name queries concatenate without spaces — assert on `textContent` in unit tests.
- The welcome step always shows `copy.startMessaging`. It never replaces the CTA with a "Connecting" status. Session restore uses auth status `restoring` and opens the workspace immediately from `dialogs.json` (Nicegram paints SQLite dialogs while DC connect continues). A paged `GetDialogs` then refreshes the list; until that returns, the chat-list title swaps from `copy.appName` to `copy.connectionSynchronizing` (or `copy.connectionOffline`). Folder badges are computed from the cached dialogs, never a second unbounded GetDialogs.

## Conversation paging and avatars

Aligned with Telegram's own clients (verified against Nicegram-Android's `LoginActivity`/`ChatLoadingCell` and the shared `AvatarDrawable` behavior):

- History and chat-list paging are sentinel-driven, never buttons or scroll-offset thresholds. `useEdgeSentinel` (`frontend/src/shared/lib/use-edge-sentinel.ts`) wraps an `IntersectionObserver` over a marker element: the transcript watches a top marker (older messages), the sidebar a bottom marker (more chats). `MessageScroller` follows the live edge without a smooth-scroll backlog while media sizes settle, and the transcript enables its marker only after it has confirmed the live edge and the reader has expressed backward-navigation intent (upward wheel, touch/pointer scrolling, or an upward paging key). Initialization and chat switching therefore cannot fetch history; once armed, reaching the marker loads the next page. Sidebar paging pauses while a search query is active.
- Leaving the transcript's live edge reveals a circular BEUI icon `Button` above the composer. It uses the Nicegram/Telegram page-down affordance, returns directly to the latest loaded message, and disappears again at the live edge. Its presence transition is limited to opacity plus a 6px/4% transform over 160ms with `EASE_OUT`; reduced motion keeps only a 120ms opacity transition. The message list itself remains motion-free.
- Dialog photos are requested with the complete Telegram dialog entity, not a stringified peer id. Channels and migrated groups need the entity's access hash; dropping it makes profile-photo resolution fail even though direct-user photos may still load.
- Paging feedback is a spinner only — never a written "Loading…" notice. `LoadIndicator` (`frontend/src/shared/ui/load-indicator.tsx`) renders a centered `SpinnerGap` with `role="status"` and an `aria-label`, fading in/out over 160 ms; the transcript wraps it in the rounded bubble that Telegram's `ChatLoadingCell` uses. The label stays accessible to screen readers but no text is visible.
- A photo gets its final box before a byte of it arrives. `MessageMedia` computes one `visualMediaBox` from the dimensions the message already carries and hands the identical `aspect-ratio` plus width to the placeholder and to the loaded `img`/`video`, so the pixels drop into a hole that is already the right shape. It caps the width rather than the height (`min(100%, aspect * 384px)`) because capping the height leaves spare room and letterboxes; a photo taller than 1:2 is boxed at 1:2 and fitted, since a sliver is unreadable. A photo message's dimensions come from its `sizes` entries (the largest of `PhotoSize`/`PhotoCachedSize`/`PhotoSizeProgressive`, as telegram-tt's `getPhotoFullDimensions` does) — teleproto's `File.width` accessor throws for photos and a photo carries no document attributes, so without that fallback the placeholder collapses to the bubble's minimum width and stretches into a vertical strip. When dimensions are genuinely absent the frame still draws a media-shaped 4:3 card (min 256px wide) instead of a strip, and scroll anchoring absorbs the swap when the real size arrives. The old placeholder had `min-h-40` and its own aspect box while the loaded image sized itself from its intrinsic ratio, so every thumbnail that landed above the reader shoved the transcript.
- The transcript re-enables browser scroll anchoring (`viewportClassName="[overflow-anchor:auto]"`). `MessageScroller` turns it off by default, which is right for a streaming agent log where growth happens at the bottom edge the reader is already following; a transcript grows _above_ the reader instead, as thumbnails, fonts and custom emoji land. Anchoring covers what cannot reserve its geometry up front — media arriving with no dimensions — and it does not fight the prepend compensation below, whose `scrollTop` assignment is absolute and computed from snapshots taken before the fetch.
- Prepending an older page must not move the read position: the request snapshots `scrollHeight`/`scrollTop` plus the first message id, and a `useLayoutEffect` applies the height delta before paint once the first id actually changes. The spinner exits with `AnimatePresence mode="popLayout"` and the store commits the page and the loading flag in one `set()`, so the spinner never distorts the compensation measurement.
- The conversation header renders an empty title while the chat resolves — no "Loading" text.
- Connection copy never occupies the strip under the conversation header. That slot is the pinned-message bar (`PinnedMessageBar`): preview text, optional `n/N` when several pins exist, click jumps via `requestJumpToMessage` and cycles to the next pin. Chats with no pins render nothing there — no "Updating…" or "Loading" banner.
- The connection has exactly one surface: the chat list title ("Connecting…" / "Updating…"). The conversation header has no error strip. Sync failures (language-level exceptions, disconnected transport, flood waits, failed catch-up, background folder refresh) stay in the main-process log and are never painted under the conversation title. A failed send or sticker is marked on its own bubble; a failed upload stays on the composer; a failed search uses the search empty state. Going offline still swaps the chat list title to "Connecting…".
- `Avatar` paints a photo when one exists and otherwise TDLib's empty userpic: the first grapheme of the title (a Latin letter uppercased, a CJK character, or an emoji) on the peer's `accent_color_id` fill. Ids 0–6 are the built-in red/orange/violet/green/cyan/blue/pink two-stop gradients; higher ids come from `updateAccentColors` RGB lists (`light_theme_colors` / `dark_theme_colors`). A cached photo (`telo-media://` or a data URL) appears immediately via the image `complete` check; while `avatarPending` is set (or while a new `src` is decoding) the slot is a circular muted pulse skeleton (`motion-reduce:animate-none`) unless a placeholder can paint immediately. After the download settles with no photo the glyph stays. This is not two-letter initials (`AB`) — Telegram Desktop `EmptyUserpic` and Android `AvatarDrawable` use one grapheme. Saved Messages is not a photo slot: chat-identifying avatars (`mark="saved"`) paint Telegram Desktop's bookmark disc (`EmptyUserpic::PaintSavedMessages`) on `bg-primary`, because TDLib models that chat as a private dialog with `getMe()` and the account often has no userpic. Message-author photos in that transcript still use the account photo (or that account's empty userpic). The photo cross-fades in over 200 ms `ease-out` with the standard image outline. Images are `loading="lazy"` + `decoding="async"`; a changed source re-fades instead of popping. beui has no Skeleton primitive, so the pulse lives inside `Avatar` rather than a new shared component.
- Transcript rows carry the author photo through the BEUI `MessageAvatar` slot: incoming rows read it from the per-peer cache with `MessageDto.senderId`, and outgoing rows read the account photo from `entities/telegram` instead of caching a copy of it per message. Telegram tails a run of consecutive messages by one author with a single photo anchored to the run's last row (`self-end`); the earlier rows keep a `placeholder` slot so the bubbles stay on one edge, and a day divider starts a fresh run. Telo shows the photo on both sides — Nicegram-Android draws it only for incoming group rows. A row that is still resolving a photo shows the `Avatar` skeleton unless `senderAvatarPlaceholder` can paint the empty userpic immediately. Unlike Nicegram, Telo renders it in one-to-one chats too, because both participants are visible in the transcript.
- A message author is an avatar peer even when it is not a dialog of its own, so a photo that lands after a row rendered arrives on the existing `chat-avatar` event keyed by that peer id. `chat-store` records it in `peerAvatars`, and rows overlay that map on the snapshot each `MessageDto` carried — messages are never repatched one by one.
- Every avatar that identifies someone is a tap target that opens their profile, the way Telegram opens a profile from a group message. The conversation header photo opens the active chat's info; a transcript photo opens its author. The target is carried by `useChatProfileStore.peerId`: null follows the active chat, a set id targets that peer. The panel resolves the id against the loaded chat list first, so a peer that owns a dialog gets the full chat profile — shared media, pinned messages, the existing actions — and only a peer with no history falls through to `workspace.getPeerProfile`, which returns the identity card (photo, title, username, bio, phone) that is all Telegram can offer for someone you have never talked to. A local placeholder with no acknowledged peer id is not pressable.
- The tap target is `PressableBlock`, not `Button`: the avatar owns its own round geometry and must not inherit button chrome. It contributes only the shared 0.96 press spring and the focus ring, and it already drops the scale under `prefers-reduced-motion`. No entrance animation was added to transcript avatars — rows render hundreds of times a day, which is squarely in the "never animate" tier.
- The info panel and the agent panel are one column, not two panels that each pick a width. Both read `RIGHT_PANEL_WIDTH_CSS` (`entities/preferences`), which resolves the `--workspace-agent-panel-width` custom property the workspace grid publishes, so the column keeps its size when the info button swaps what is inside it and the single resize handle drives whichever panel currently occupies the slot. The width has to stay a definite length: the panels sit in an `auto` grid track, and a percentage there has no base to resolve against — the profile column used `min(100%, 22.5rem)` and would either balloon into the free space or collapse to a strip depending on what was inside it.
- Profile detail rows read value first with the field name under it (`@mina` over `Username`), which is Telegram's `TextDetailCell` order — the handle is what the reader came for. They are `OptionRow`s from `shared/ui`, so they inherit the 40px target, the hover fill, and the shared 0.96 press spring; `OptionRow` grew a `wrap` option for the bio, whose value is prose rather than a name. Tapping a row copies its value, and the field name is replaced in place by "Copied" — a static cue, so the confirmation never depends on motion and the app needs no toast surface. Phone numbers carry `tabular-nums`. The identity block (photo, name, status line) is one `ProfileIdentity` shared by the dialog profile and the peer card rather than two copies.
- Bio text is not linkified. Telegram linkifies it from server-side entities, and `PeerProfileDto.bio` is a plain string, so a URL in a bio renders as wrapped text until the contract carries entities. Detecting links client-side would be a second, weaker copy of the entity mapping that `MessageRichText` already owns.

- The composer carries no persistent formatting strip. Telegram's own field has none: formatting lives on the shortcuts (`Ctrl+B/I/U`, `Ctrl+Shift+X/M/P`) and on the right-click menu over a selection. The menu holds Copy / Cut / Paste / Select all, then a labelled Formatting group of checkable items showing their shortcuts, then Clear formatting. Telegram Desktop nests that group in a submenu; the registry has no submenu primitive, so it is labelled rather than nested.
- Menu actions take the range the menu snapshotted when it opened, never the live textarea. By the time an item is clicked the menu owns focus and the browser has collapsed the selection, so re-reading it would format nothing — a failure invisible to a unit test that fires the click synchronously. Applying a format restores the selection afterwards, so a second format can stack on the same words.
- Every clipboard edit goes through the same entity-aware splice as mention insertion. The composer owns body and entities together; letting the browser mutate the textarea directly would leave the spans behind.
- An icon button that is currently active reads the same everywhere: `variant="secondary"` plus a filled icon, never a hand-rolled tint. That covers the header toggles, the pin, and the emoji and sticker picker tabs.

## Message bubbles

- Message bodies render through the BEUI `MessageRichText` primitive exported by `shared/ui`. Telegram UTF-16 ranges become semantic React elements (`strong`, `em`, `code`, `pre`, `blockquote`, `time`, safe links); never use `dangerouslySetInnerHTML`. Unknown, crossing, or out-of-bounds entities stay plain text. Spoilers use an accessible reveal button with a static obscured surface and no entrance animation; nested links remain inert until reveal.
- Message attachments render through the BEUI `MessageMedia` primitive. The chat entity store owns progress keyed by opaque media id; widgets supply localized labels and commands, never filesystem paths. Progress uses tabular byte counts and a static bar, while the existing BEUI button press feedback is retained for download, cancel, and retry.
- A sticker is a document, but it is never an attachment card. `MessageMedia` routes `kind: "sticker"` to the `Sticker` primitive in `shared/ui`, which draws it with no file name, no byte count and no download button — the three things Telegram never shows for one. The transcript also drops the bubble for a sticker that carries no caption, reply quote or forward header, so the sticker sits straight on the background the way `ChatMessageCell` draws it. A caption brings the bubble back, because that chrome needs a surface.
- The three Telegram encodings all render from the same box: `image/webp` as an `img`, `application/x-tgsticker` as gzipped Lottie, and `video/webm` as a silent looping `video`. `MessageStickerDto.format` carries which one, derived in the backend from the mime type, so the renderer never sniffs bytes. The box is sized from the document's own dimensions capped to 180px on the longest side — the desktop equivalent of the 170dp cell Telegram-Android uses — and it is reserved before the download lands, with the alt emoji held in the same slot, so nothing reflows when the sticker arrives.
- `.tgs` is gunzipped with Chromium's `DecompressionStream("gzip")` and played by `lottie-web`, imported lazily so the ~400KB player only loads for a chat that actually has an animated sticker. The renderer reads those bytes with `fetch` over `telo-media:`, which is why that scheme is `corsEnabled` and listed in the page CSP's `connect-src`. A sticker that fails to decode falls back to its emoji and logs the reason rather than leaving a hole.
- Sticker motion is content, not chrome, so animated and video stickers loop on their own the way Telegram plays them — the "don't animate high-frequency UI" rule governs interface decoration, not the payload the message is made of. Under `prefers-reduced-motion` both hold their first frame and expose a full-bleed play control, which is the gentler equivalent rather than a missing sticker. A reader who turns the `loopStickers` preference off gets a single pass and then that same held frame and control; the transcript threads the preference to `MessageMedia` as `loopStickers` and the primitive takes it as `loop`, because `shared` never reads a preference itself. Reduced motion still outranks the choice. No entrance animation was added: the message row already has one.
- A context menu owns `Escape` from the moment it opens, through a capture-phase document listener - not from the moment focus lands inside it. The first item is focused a frame after open, so a content-scoped handler silently drops the keystroke of anyone who right-clicks and dismisses in the same breath. The menu also reads the text selection frozen at open time: opening moves focus and the live selection is already gone by the time an item runs, which is why the transcript can still name the action `Copy Selected Text` over a highlighted run and `Copy Text` over the whole bubble.
- Emoji and stickers share one composer button, the way Telegram does: a single `MorphPopover` with `Emoji` / `Stickers` tabs at the top of the panel. Both sections stay mounted and the inactive one carries the `hidden` attribute, so tabbing away never drops a search query, a scroll position, or the loaded sets. The sticker section loads the lightweight `workspace.getStickerCatalog()` the first time it is actually shown and resolves only the selected pack. The panel keeps one width across both tabs so switching sections never reflows it sideways. Catalog loading reserves the final search, heading, fixed-height grid, and pack-tab geometry with skeletons; resolving a pack or search replaces only the 64px sticker cells, while unresolved 28px pack thumbnails retain exact-size skeletons. Loading prose and generic sticker icons are not valid placeholders because both cause a visible size or content swap. Cells draw through the same `Sticker` primitive and the same media pipeline as the transcript — each cell asks for its own document and reads the shared download slot — so a sticker is already cached by the time it is picked, and the optimistic bubble reuses that media id and paints on the first frame. A resolved pack tab uses its first real sticker, held still at thumbnail size, instead of substituting that sticker's alt emoji.
- Holding a picker or set-sheet cell for 400ms opens Telegram's transient large sticker preview. While the pointer stays down, moving across neighboring cells scrubs the preview to the sticker under the pointer; releasing closes it and suppresses the click that would otherwise send the original sticker. Moving beyond the gesture tolerance before the hold threshold remains an ordinary scroll/drag. The transient surface has no interactive controls, does not intercept hit testing, and is the top overlay layer (`10002`, above popover `9999`, context menu `10000`, and modal `10001`); right-click remains the persistent preview/favorite/recent-actions path.
- Picker cells pass `still`, which holds animated and video stickers on their first frame with no play control. A wall of looping animations is the repeated attention cost that motion restraint exists to prevent, and a screenful of simultaneous players is a real frame budget. The transcript, where a sticker is the message, keeps them playing.
- Tapping a sticker opens its set, the way Telegram does. `MessageMedia` wraps the sticker in a `PressableBlock` only when a set exists, so a sticker with nothing to open never becomes a control that does nothing. The sheet is a `CenterMorphModal` — centred, because it is not anchored to a trigger — listing the set with an add or remove action; a set reached from a received sticker may not be installed, which is the point of the action. Picking from the sheet sends, like the composer picker.
- Scrollbars follow Apple's overlay convention and Telegram Web K's `scrollbar-color: … transparent`: one global rule set in `app/styles/index.css` gives every scroller an 8px alpha thumb on a transparent track, themed through `--scrollbar-thumb`. Author rules are mandatory, not cosmetic: without them Chromium falls back to the bordered legacy scrollbar whenever the OS forces scrollbars always-on. Short horizontal strips (folder tabs, suggestion pills) never show a scrollbar at all — they hide it (`scrollbar-width: none` + `::-webkit-scrollbar: hidden`) and hint overflow with the `useScrollFade` mask instead of a track.
- A `custom-emoji` entity names a sticker document from inside the text. `MessageRichText` takes an optional `renderCustomEmoji`, supplied through context so the registry primitive keeps its signature: without it the glyph the entity covers renders as plain text, which is Telegram's own fallback when the document is unavailable. The transcript supplies a renderer that resolves the document through `workspace.getCustomEmoji`, caches it in `chat-store.customEmoji`, and draws it at 20px — line height, so it reads as a character rather than an attachment wedged into a sentence. An id Telegram no longer serves caches as null so the entity settles on its glyph instead of retrying every render.
- Custom emoji reuse the sticker media id space (`sticker/<documentId>`) and the same download pipeline, because a custom emoji is a sticker document. Nothing about them is a second media path.
- A reply renders as a quote block inside `MessageBubbleContent`, above the body: a 2px accent left border (`border-l-2 border-primary`), the quoted sender name in `text-primary`, and the quoted body truncated in `text-foreground/70`. The data is the `replyTo` snapshot on `MessageDto`, so the block survives edits of the original message.
- An edited message shows the `edited` marker inside `MessageMeta` — beside the timestamp on the last text line, or in the footer row for text-free bubbles — whenever `editedAt` is set.
- The composer is controlled by the send-message feature and clears only after its async submit succeeds. A failed send or edit keeps both the text and reply/edit context so the user can retry without reconstructing the draft. Entering edit mode focuses the field with the caret behind the prefilled body (the layout effect fires only on the transition into edit mode, so a later re-render never steals a moved caret); leaving edit mode — the global Escape, the bar's cancel, or a finished edit — restores the chat's own unsent draft, because an edit borrows the field rather than consuming the draft.
- Earlier history loads only when the reader reaches the transcript's leading-edge sentinel. Prepending compensates the viewport by the added content height, so the message under the reader does not move. Historical pages never receive message entrance animation. The unread divider uses the loaded read id when present and otherwise derives the unread suffix from `unreadCount`; opening a chat never walks backward through history just to place the divider.
- Bubble geometry is Telegram Desktop's, not the registry default: padding `margins(11px, 8px, 11px, 8px)`, 16px corners with a 6px corner on the avatar side inside a same-author run (`bubbleRadiusSmall`), 430px max width, 2px between run rows and 8px at an author switch (`msgMarginTopAttached`), 33px avatar in a 40px column, and line-height 1.3125 from Telegram Web K. Every value is a `--message-*` custom property in `frontend/src/app/styles/index.css` (with its source named in the comment there) that the conversation view threads through classNames; never hand-write these numbers in a component. A run by one author gets one sender-name header, on its first row, and one avatar, anchored to the bubble bottom of the run's last row.
- The meta — `edited` marker, timestamp, delivery ticks — rides the last line of the message text: a text-free spacer floats at the end of the text run through `MessageRichText`'s `trailing` slot, and the visible `MessageMeta` overlays the bubble's bottom-right, measured into the spacer's width (Telegram Web A floats `.MessageMeta` inside `.text-content`; Web K reserves the width with an invisible inline copy). The overlay lives outside the text div so the transcript's text nodes stay exactly the message body, and the text div is `flow-root` so a last line too full for the meta wraps the spacer below and grows the bubble a line instead of letting the meta overlap the glyphs. A row with no text run (media without a caption, a bare sticker) or with an inline keyboard keeps the `MessageFooter` row. Delivery state uses Telegram's four-glyph alphabet — clock while sending, one check when the server acknowledged, two when read, a filled warning on failure — mapped by the exhaustive `deliveryGlyphKind` switch in `widgets/conversation-view/ui/delivery-status.ts`; a single `Checks` icon at two stroke weights is not a state distinction. The "sending" glyph is static: sending is a dozens-of-times-a-day interaction, the tier where a spinner is a repeated attention tax.
- Reactions render as full-round pills under the bubble (Telegram's outside position, Web K's `.reactions-block`), reversed for outgoing messages so the first chip sits on the bubble's outer edge. Chips come from the `react-to-message` feature: one reaction per account (Telegram's non-premium shape), toggling the chosen emoji clears it, and the picker's emoji list is Telegram's own allowed set from `workspace.listAvailableReactions` (`getMessageAvailableReactions`), never a hardcoded list. The pill is a 30px surface inside a 40px beui `Button` hit box. A failed toggle reverts the optimistic chip and stays quiet — no red `role="alert"` under the bubble, matching Telegram Desktop. Chip appearance/disappearance bridges with a 150ms opacity-plus-scale transition (`EASE_OUT`, reduced-motion honored); the count stays static — motion never lands on a numeral someone else changed.

## Motion

- High-frequency rows change surface color without scaling or lifting.
- Chat rows set the BEUI button press scale to `1`; chat selection, search filtering, and page insertion are high-frequency navigation and remain motion-free.
- Buttons use a restrained `0.96` press scale and no hover scale.
- Interactive transitions name the changing properties and last no more than 200 ms.
- The workspace's right-side panels share one persistent `WorkspaceSidePanel` shell backed by beui's `AnimatedSidebar` in offcanvas mode. Agent and profile content are slots inside that shell; they must not mount their own provider or sidebar. The persistent outer column springs to zero width while the inner surface remains fixed to prevent text reflow, so every slot keeps the same entrance and exit behavior. The component owns the spring timing, inner cross-fade and slide, reduced-motion fallback, and the `aria-hidden` + `inert` guard on the closed panel. Its width comes from `RIGHT_PANEL_WIDTH_CSS`. Never conditionally mount the animated shell or hand-write a CSS transition / `motion` wrapper around a panel; if the reveal itself must change, change the vendored component.
- Agent waiting states are skeletons, not status prose. Before a reply streams, the panel renders `ResponseSkeleton` (beui `TextShimmer` label over `Skeleton` bars inside a `SkeletonGroup`); the placeholder label is never injected as message content. These primitives carry their own reduced-motion handling, so consumers must not add local motion media queries.
- Agent replies use Streamdown for incremental Markdown parsing and block memoization inside beUI's `StreamingResponse`. Incomplete Markdown is repaired while streaming, new words animate unless reduced motion is on, and fenced code uses beUI's `CodeBlock`. The adapter transforms citation links and known mentions only in parsed prose nodes, omits raw HTML, sanitizes URLs, and holds back an unfinished trailing in-app link.
- References in agent replies are inline, not a chip row. A citation is an ordinary `<a href="telo://message/…">` rendered as a small superscript number in the text; an `@Name` of a known peer is a borderless inline chip (avatar plus name) on a `bg-foreground/8` tint, `inline` rather than `inline-flex` so the line height does not grow. Neither is a beui `Button`; navigation is a delegated click handler on the `telo://` scheme at the app root.
- Failures are quiet. Transport and provider errors never reach the transcript as text; the UI stays on the loading state while the backend absorbs short waits, and a run that does fail shows one muted status row with a retry action.
- Suggested prompts are small borderless pills (28px, `rounded-full`, `text-xs`, translucent `bg-background/90` with a hairline shadow) floating over the transcript's bottom edge, directly above the composer. The row scrolls horizontally with its scrollbar hidden and a `mask-image` gradient (`useScrollFade` / `scrollFadeMask` in `shared/lib`) that fades only the overflowing edge; a jump-to-latest button shares the strip's right end while the transcript is scrolled up. Pills leave when they no longer apply, never become a toolbar of segmented controls, and the composer never exposes developer-facing panels (payload previews, run logs, scope pickers) in the consumer product.
- Mention autocomplete is one shared listbox. `MentionAutocomplete` (`shared/ui`) renders `OptionRow`s with the peer's `Avatar` in the `leading` slot; the chat composer and the agent composer both use it over their own item adapters (`filterMentionItems` in `shared/lib/mention-query`), so the two menus look and behave identically.
- Context handed to the agent is shown as compact cards inside the `PromptInput` attachment slot (`AttachedMessageCards`): rounded-lg chips with a 6×6 remove button whose hit area is extended with a pseudo-element, entering at `scale 0.95 → 1` and leaving at `scale 0.97`, both under 200 ms with `EASE_OUT`, `AnimatePresence initial={false}` so restored state does not replay.
- Composer-staged photos preview from `URL.createObjectURL`, the same `previewBlobUrl` path Telegram Web A uses in `buildAttachment`. The page CSP therefore lists `blob:` on `img-src` and `media-src` (Telegram Web A's webpack CSP does the same); downloaded chat media still uses `telo-media:`. Without `blob:`, Chromium paints the broken-image glyph in the tray even though the object URL is valid. `MessageAttachmentTray` sits in that same `attachmentPreview` slot: thumbs enter at `scale 0.95 → 1` and leave at `scale 0.97` over 180 ms `EASE_OUT` (120 ms opacity-only under reduced motion), growing from the composer's bottom-left, matching the agent cards. Attachments are not restored across remounts, so the first thumb is allowed to enter.
- Reduced-motion preferences disable nonessential movement globally. The device setting and the app's own `reduceMotion` preference resolve through one `MotionConfig` at the app root (`frontend/src/app/motion-preferences.tsx`): `always` while the preference is on, `user` otherwise, so the override only ever adds restraint and the device setting stays authoritative. Surfaces read the resolved value with `useReducedMotionConfig()` from `motion/react` — never `useReducedMotion()`, which sees only the device setting and ignores the provider.

## Components are small and focused

- A component should do one thing.
- Extract a new component when a file grows beyond ~300 lines or when a block is reused.
- Components receive data and callbacks through props; they do not fetch their own data unless they live in a feature slice and that is the slice's explicit responsibility.

## Layout rules

- Use Flexbox to partition the screen into stable regions (header, content, footer).
- Window-edge title bars preserve native controls. macOS uses Electron's `hiddenInset` plus Window Controls Overlay; leading renderer chrome reads `env(titlebar-area-x)` through `window-titlebar-safe-leading` and centers content within `env(titlebar-area-height)` through `window-titlebar-safe-content` instead of hardcoding traffic-light coordinates. Windows hides the native title bar (`titleBarStyle: "hidden"`) and overlays min/max/close in the same 56px header band. Linux GTK ignores a hidden title bar, so the window is frameless and the renderer paints close/min/max (`WindowControls`) with `--window-controls-start` padding on the leading header. Chromium's File / Edit / View application menu is hidden (`Menu.setApplicationMenu(null)`, `BrowserWindow.setMenu(null)`, and `autoHideMenuBar`) so it does not sit above the workspace.
- Only designated containers scroll. Do not allow the body or arbitrary containers to scroll.
- Set `min-height: 0` on every flex container that participates in the scroll chain.
- The page root should fill the viewport (`min-h-dvh` / `h-dvh`).

## Accessibility

- Use semantic HTML (`button`, `a`, `label`, `nav`, `main`).
- Every interactive element must have an accessible name.
- Do not build fake buttons or links with `div` + click handlers.
- Shell layouts render a skip-to-content link as the first tab stop: visually hidden (`sr-only`), visible on focus (`focus:not-sr-only`), pointing at the `id` anchor on the main content surface. The label comes from `copy.skipToContent`.
